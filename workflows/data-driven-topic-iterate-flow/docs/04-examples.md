# 使用示例

以下示例均来自 `scripts/run_flow.py` 对 `examples/input.json` 的实跑结果（退出码 0）。

## 示例 1：标准输入 —— 5 个在跑选题的周迭代

**输入**（节选）：

```json
{
  "week": "2026-W40",
  "ltv": 540,
  "channels": [{"name": "付费投放（测试）", "spend": 900, "paying": 4}],
  "active_topics": [
    {"topic": "churn 分析实战（PH 发布配套）", "channel": "Product Hunt Launch", "week_signups": 82},
    {"topic": "付费投放素材组 A/B", "channel": "付费投放（测试）", "week_signups": 96}
  ]
}
```

**输出**：`out/复盘与选题迭代清单.xlsx`（渠道判定+权重更新+下周计划+汇总）+
`out/topic_iterate_result.json`。加权 3 / 暂缓 1 / 降权 1，每个选题带依据。

## 示例 2：整改前后对照 —— 从「凭手感续写」到「权重规则迭代」

| 阶段 | 做法 | 结果 |
|---|---|---|
| 改造前 | 哪个题写顺手就继续写哪个；付费投放素材组写了一个月不停 | 付费投放当月烧 ¥3,600 CAC ¥300；高产选题（SEO 教程）反而断更 |
| 改造后 | 周日跑迭代：付费投放 CAC ¥225 ≥ ¥180 → 素材组降权转向；SEO 教程 CAC ¥20 → 加权系列化 | 整体 CAC 降至 ¥43；SEO 教程系列连续 4 周每周带来注册 |

**关键差异**：写什么不该由「顺手」决定，由「该选题所在渠道的 CAC 与漏斗
状态」决定——权重规则把手感替换成了可复核的判定。

## 示例 3：注册最多 ≠ 加权（追热点的反例）

付费投放素材组本周 96 注册，全场最高，但渠道 CAC ¥225 超判定线 →
权重 ↓ 降权。**单周注册数是虚荣指标，CAC 才是判定线**——这条规则
专门防「追着量大的渠道加码」的本能。

## 示例 4：漏斗破段的选题暂缓

Reddit 渠道选题照跑但「→ 暂缓」：落地页→注册 7.0%、注册→激活 19.0% 双破段。
此时写再多新帖，流量也会在落地页漏掉——先修漏斗（首屏承诺+onboarding），
修完复测，选题解冻。低于下限先修漏斗，不是加投放/加选题。

## 示例 5：空选题清单的正常退出

**输入**：`active_topics` 缺失（新账号第一周）。

**输出**：「无在跑选题」占位清单，退出码 0；下周计划页如实写
「先跑 daily-topic-mine-flow 挖新题」——不编造选题，保持周迭代日志连续。
