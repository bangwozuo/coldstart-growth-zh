# 使用示例

以下示例均来自 `scripts/run_flow.py` 对 `examples/input.json` 的实跑结果（退出码 0）。

## 示例 1：标准输入 —— 13 帖 → 1 张选题卡 + 4 个观察主题

**输入**（节选）：

```json
{
  "source": "r/SaaS + r/SideProject + r/indiehackers",
  "window_days": 7,
  "posts": [
    {"id": "P013", "subreddit": "r/SaaS", "title": "Setup wizard is too confusing - 40% drop off at step 2 of onboarding", "ups": 65, "num_comments": 27, "age_hours": 40}
  ]
}
```

**输出**：`out/每日选题清单.xlsx`（选题卡+观察池+参与队列+汇总）+
`out/topic_mine_result.json`。入选「上手门槛」1 张（P005/P013/P014，
3 帖达标，带 URL 证据链）；定价 2/3 等进观察池；可参与 8 帖。

## 示例 2：整改前后对照 —— 从「想到什么写什么」到「证据链选题」

| 阶段 | 做法 | 结果 |
|---|---|---|
| 改造前 | 每天看一条痛帖就有感而写，选题全凭手感 | 写了 4 篇，阅读中位数 200，无一篇带来注册 |
| 改造后 | 只写 ≥3 帖证据的主题：「上手门槛」选题卡（3 帖+URL）→ 五角度出钩子 → devlog 成稿 | 该主题连续产出 2 篇，均带来自然注册（周复盘回捞确认） |

**关键差异**：证据链选题的本质是「先证明有需求，再投入写作时间」——
3 帖门槛过滤掉的是作者自嗨。

## 示例 3：单帖不成选题的执行

「隐私安全」1 帖（P009，热度 247.0）、「移动端」1 帖（P010）——即使单帖
热度高也只进观察池。P010 一帖双主题（性能+移动端）各按 1 帧计，不重复累加。

## 示例 4：上游漏判的发现与修复闭环

P013「Setup wizard is too confusing - 40% drop off…」初版词表未命中被判噪音，
「上手门槛」只有 2 帧证据进不了选题。模型复核存疑项后确认漏判 → 反哺上游
community-post-insight 词表（补 drop off / too confusing / gave up / how do you
decide 等）→ 回归测试后该帖正确判痛点 → 主题凑满 3 帖入选。
**工作流的价值之一就是给上游技能装了一个每日运行的回归探测器。**

## 示例 5：空输入正常退出

**输入**：`posts: []`（Reddit API 限额用尽）。

**输出**：「今日无目标帖」占位清单，退出码 0——不算失败，保持每日流程日志
连续；明日重跑或改用人工粘贴。
