# 痛点卖点匹配

把社区里挖到的真实痛点与产品功能配对，产出「第一眼让人对号入座」的钩子文案。
钩子骗来的点击会在落地页加倍还回来——所以每条钩子都要过兑现度自检。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_dev_01_sk02` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 出海增长官 |
| 能力族 | 内容生成型 · 钩子策略 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | 高（所有营销类员工复用） |
| 资产形态 | 深度提示词（无脚本依赖、无模型调用、无 API Key） |

## 能力描述

1. **配对规则**：用户原话里的场景 × 功能带来的具体改变 = 钩子；功能兑现不了的
   痛点如实判「错配」弃用，不硬凑
2. **五种角度**：痛点瞬间 / 前后对比（须有真实数字）/ 身份共鸣 / 反共识 / 成本账
3. **量化自检**：X/Reddit 版 ≤90 字符、落地页首屏 ≤20 字；至少一个具体细节
   （数字/时间/工具名/场景）；「3 秒对号入座」判定法过滤太泛的钩子
4. **合规内建**：无绝对化用语、数字必须有输入依据、社区使用须披露开发者身份

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `brief` | string | ✅ | 产品简述（功能清单 + 可兑现的效果数据） |
| `painpoints` | array | ⬜ | 社区痛点原话（来自 community-post-insight 的产出） |
| `platform` | string | ⬜ | 用途场景：X / Reddit 评论 / 落地页 / devlog；不同场景钩子形态不同 |

## 输出规格

- `hooks`：钩子候选（按五种角度分组，附具体细节与适用场景）
- `pairs`：痛点-功能配对表（含「错配弃用」判定）
- `self_check`：逐条自检结果（长度 / 具体度 / 兑现度 / 合规）与弃用原因

## 使用步骤

1. 把 `prompt.txt` 全部内容粘贴为系统提示词（Coze / WorkBuddy / Dify / Claude / ChatGPT 均可）
2. 提供产品简述 + 痛点原话 + 使用场景
3. 得到配对表、按角度分组的钩子候选与自检结果；人工确认承诺可兑现后使用

## 边界（不做的事）

- ❌ 不编造用户案例、数据与效果承诺；数字必须有输入依据
- ❌ 不为未实现的功能写钩子；错配痛点弃用并说明
- ❌ 不伪装用户口吻；社区场景披露开发者身份
- ❌ 不使用绝对化用语与「保证」「必」类承诺词

## 调用示例

**输入**（`examples/input.json`，节选）：

```json
{
  "brief": "ChurnLens：给独立开发者的流失分析 SaaS。Stripe 同步开箱即用；周 cohort 视图；plain-English 流失报告。实测：接入 15 分钟。",
  "painpoints": [
    "Struggling with churn - users sign up, never come back after day 3",
    "Is there a tool that turns Stripe invoices into a simple monthly P&L?"
  ],
  "platform": "Reddit 评论"
}
```

**输出**（见 `examples/output.md`）：痛点 1 配对成功 → 4 条钩子（含「Day 3,
your signups quietly disappear」）；痛点 2 判定错配（产品不做 P&L）→ 如实弃用。
自检 4/4 通过，1 条带未实测数字的钩子被打回降级。
