# 叙事改写

把技术日志（devlog）改写成用户视角的 build-in-public 内容：让不写代码的读者
想看完并愿意回一句。不编数据、不装用户、不写软文。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_dev_01_sk03` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 出海增长官 |
| 能力族 | 内容生成型 · 叙事改写 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | 中 |
| 资产形态 | 深度提示词（无脚本依赖、无模型调用、无 API Key） |

## 能力描述

1. **五段式叙事**：钩子（前 2 行决定 80% 完读率，必须含数字/时间/场景细节）→
   冲突 → 尝试 → 结果（真实数字，含没修好的部分）→ 一个具体提问
2. **视角转换**：每个技术动作回答「对用户意味着什么」（重构缓存层 → 页面 8 秒
   到 2 秒）；非必要术语 ≤2 个/百字；用户收益排前，技术选型排后
3. **数据诚实**：只用输入中的真实数字，没有就不写；不估算不膨胀（47 用户
   不写成「近 50」）；翻车周照常发；不引用不存在的用户语录
4. **平台收口**：X thread 3-7 条（首帖 ≤280 字符）/ Reddit 正文 150-300 词 /
   Indie Hackers 长文 600-1200 词

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `content` | string | ✅ | 原始 devlog（技术视角的原始日志） |
| `platform` | string | ✅ | X/Twitter / Reddit r/SideProject / Reddit r/SaaS / Indie Hackers / dev.to |
| `metrics` | object | ⬜ | 本周真实数据（用户数/MRR/星标），仅输入的数字会出现在成稿中 |

## 输出规格

- `adapted_content`：成稿正文（五段式）
- `changes`：改动说明表（原文技术视角 → 改写后用户视角 → 理由）
- `constraints_checked`：约束核对表（钩子细节 / 术语密度 / 数字无新增 / 提问 / 平台上限）

## 使用步骤

1. 把 `prompt.txt` 全部内容粘贴为系统提示词（Coze / WorkBuddy / Dify / Claude / ChatGPT 均可）
2. 提供原始 devlog + 目标平台 + 本周真实数据（有则给，没有则不给）
3. 得到成稿 + 改动说明 + 约束核对表；人工确认后再发布

## 边界（不做的事）

- ❌ 不新增输入中没有的数字、用户语录、效果承诺；traction 造假 = 社区永久拉黑
- ❌ 不伪装用户口吻，开发者身份必须披露
- ❌ 不在禁止自推的 sub 版本里放产品链接（9:1 参与比约束）
- ❌ 不用「最」「第一」「100%」等绝对词；对外发布保留人工确认

## 调用示例

**输入**（`examples/input.json`，节选）：

```json
{
  "content": "本周重构了缓存层：引入 Redis 做二级缓存，页面的平均响应时间从 8s 降到 2.1s。顺便把导出改成了队列异步处理。下周计划做 Webhook 重试。",
  "platform": "Reddit r/SideProject",
  "metrics": {"users": 47, "mrr_cny": 312}
}
```

**输出**（见 `examples/output.md`）：成稿以「凌晨 1 点用户消息」钩子开场，
「重构缓存层」翻译为「页面从 8 秒等到 2 秒」，全部数字来自输入（47 用户 /
¥312 MRR / 8s→2.1s），结尾附一个具体提问；约束核对 5 项全过。
