# 发布排期

把待发布内容排成可执行的周排期表：每个动作有明确时间点、前置条件与人工
确认环节。**不自动执行任何发布**——所有对外发布由人工执行，本技能只产出
排期与提醒清单。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_dev_01_sk06` |
| 类型 | **`atomic`（原子技能，T4 调度型）** |
| 所属员工 | 出海增长官 |
| 能力族 | 调度编排型 · 发布排期 |
| 复杂度 | `S` |
| 阶段 | `P1` |
| 复用度 | 高（一稿多发、PH 发布共用） |
| 资产形态 | SOP 深度提示词 + 只读连接器（无平台写权限、无 API Key） |

## 能力描述

1. **时间轴规则**：PH 周二至周四、00:01 PT 上线（避开周末低谷，投票窗口
   最长）；X 工作日 09:00-11:00 / 20:00-22:00（目标受众时区）、散帖 ≤3/日；
   Reddit 工作日 06:00-08:00 EST、同 sub 间隔 ≥3 天；小红书午休+睡前双高峰
2. **前置条件检查**：格式过规格核对 / sub 版规与 9:1 达标 / PH 素材齐备
   （5 图 + ≤60s 视频 + tagline ≤60 字符 + 首评草稿）/ 数据真实 / AI 标识
3. **人工确认点**：排期确认（生成后）→ 发布前确认（每动作执行前）→
   发布后确认（1 小时内 PH 评论值守启动、Reddit 30 分钟首次互动检查）
4. **只读连接器与降级**：Plausible / Reddit API / X API 全部只读；任一不可用
   时排期照常产出、对应检查项标「未核对-降级」，不阻塞不编造

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `items` | array | ✅ | 待发布条目（标题 / 目标平台 / 内容形态 / 关联素材状态） |
| `week_start` | string | ⬜ | 排期起始日（默认下周一） |
| `audience_tz` | string | ⬜ | 目标受众时区（默认 America/Los_Angeles） |

## 输出规格

- `schedule`：周排期表（日期 / 时间 / 平台 / 内容 / 前置条件 / 状态 / 确认点）
- `conflicts`：冲突与处理（版本撞期、连发自推、素材缺失）
- `degraded_checks`：降级标注（连接器不可用的未核对项）

## 使用步骤（SOP）

1. 汇总本周待发布内容与素材状态（来自 platform-format-adapt 的核对结论）
2. 把 `prompt.txt` 全部内容粘贴为系统提示词，生成周排期表
3. **排期确认**（人工）：检查与产品节奏的冲突
4. 每个动作执行前走**发布前确认**；发布后 1 小时走**发布后确认**
5. 周末用 weekly-data-review 复盘本周各动作效果，滚动调整下周排期

## 边界（不做的事）

- ❌ 不自动执行任何发布动作；无平台写权限（连接器全只读）
- ❌ 不为刷量动作排位：不刷 upvote、不买假用户、不安排点赞小组
- ❌ 9:1 不达标或同 sub 间隔 <3 天的自推动作直接拒绝排出
- ❌ 数据不真实的版本不予排期

## 调用示例

**输入**（`examples/input.json`，节选）：

```json
{
  "week_start": "2026-10-05",
  "audience_tz": "America/Los_Angeles",
  "items": [
    {"title": "ChurnLens PH Launch", "platforms": ["Product Hunt"], "material_ready": false},
    {"title": "v0.9 devlog", "platforms": ["Reddit r/SideProject", "X/Twitter"], "material_ready": true}
  ]
}
```

**输出**（见 `examples/output.md`）：PH 排到周三 00:01 PT 并标「待备料
（缺 demo 视频）」；Reddit 排周二 06:00 EST（9:1 达标前提）；X thread 排
周二 09:00。1 处冲突（PH 与 Reddit 间隔仅 1 天 → 建议拉开）已列出。
