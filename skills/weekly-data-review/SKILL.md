# 周度数据复盘

把本周各渠道原始数据算成一张「留/停」决策表：每渠道 CAC、漏斗各级转化率、
是否达到 CAC < LTV/3，以及下周行动。只做诊断与建议，不代做资金决策。

## 能力描述

1. **归因口径**：UTM 为主、引荐域兜底，冲突以 UTM 为准并标注冲突数；无主无引荐
   单列「直接/未知」；归因窗口默认 7 天
2. **漏斗体检**：CTR 2–5% / 落地页→注册 8–15% / 注册→激活 20–40%，逐渠道逐段
   比对，低于下限给处理原则（先修漏斗，不加投放）；高于上限核实流量真实性
3. **渠道判定**：CAC = 花费÷付费数（不是注册数）；CAC < LTV/3 保留/加码，
   ≥ LTV/3 停投；自然渠道考核激活率；单渠道试错上限 ¥300/次；连续 2 周达标才加码
4. **样本保护**：周注册 < 30 的渠道只报值不下结论，标注「样本不足」

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `week` | string | ✅ | 复盘周（如 2026-W40） |
| `ltv` | number | ✅ | 用户 LTV（¥；估算须注明口径），缺脚本将拒绝执行而非猜默认值 |
| `channels` | array | ✅ | 渠道列表，每条含 `name/spend/impressions/clicks/signups/activated/paying/revenue` |

## 输出规格

- `summary`：保留/停投渠道、整体 CAC、判定线（LTV/3）
- `channels`：逐渠道明细（各级转化率 / CAC / ROAS / 漏斗体检 / 判定）
- `actions`：下周行动表（渠道 / 行动 / 预算）
- 产物文件：`out/周度复盘报告.xlsx`、`out/渠道漏斗对比.png`、`out/review.json`

## 使用步骤

### 方式一：纯提示词（最快）

1. 把 `prompt.txt` 全部内容粘贴为系统提示词
2. 提供本周各渠道数据与 LTV
3. 得到漏斗体检、渠道判定与下周行动表

### 方式二：带脚本（精确计算 + 产出 Excel/PNG）

```bash
python3 <SKILL_DIR>/scripts/weekly_review.py --input input.json --outdir out
python3 <SKILL_DIR>/scripts/weekly_review.py --demo     # 无输入也能看效果
```

**分工**：脚本算转化率/CAC 并逐条比对基准（不漏不猜）；模型复核归因口径的
合理性与「样本不足」渠道的表述；停投/加码由人工确认后执行。

## 边界（不做的事）

- ❌ 不编造或补齐缺失数据；缺哪列列清单让用户补，`ltv` 缺失直接拒绝执行
- ❌ 不代做资金决策：停投/加码只出建议，人工确认后执行
- ❌ 不给「继续观察」类无结论输出；每渠道必须三选一（保留/整改/停投）
- ❌ 数值以脚本输出为准，不要自己算

## 调用示例

**输入**（`examples/input.json`，节选）：

```json
{
  "week": "2026-W40",
  "ltv": 540,
  "channels": [
    {"name": "付费投放（测试）", "spend": 900, "impressions": 50000, "clicks": 1500, "signups": 96, "activated": 17, "paying": 4, "revenue": 320},
    {"name": "X buildinpublic", "spend": 60, "impressions": 30000, "clicks": 600, "signups": 54, "activated": 16, "paying": 5, "revenue": 745}
  ]
}
```

**输出**（脚本实跑，5 渠道）：保留 4（PH、Reddit、X、SEO 博客），停投 1
（付费投放 CAC ¥225 ≥ 判定线 ¥180，且落地页→注册 6.4%、注册→激活 17.7% 双破段）；
整体 CAC ¥43.2。详见 `examples/output.md`。
