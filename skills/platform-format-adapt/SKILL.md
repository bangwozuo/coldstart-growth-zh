# 平台格式适配

把一篇母稿改写成 N 个平台的合格版本：每个版本符合该平台字数上限、结构与调性，
核心信息一条不丢、一条不编。只做「同源多形」改写，不做内容策划。

## 元信息

| 字段 | 值 |
|------|-----|
| ID | `de_dev_01_sk04` |
| 类型 | **`atomic`（原子技能）** |
| 所属员工 | 出海增长官 |
| 能力族 | 内容生成型 · 格式适配 |
| 复杂度 | `S` |
| 阶段 | `P0` |
| 复用度 | 极高（一稿多发、发布排期共用） |
| 资产形态 | 深度提示词（无脚本依赖、无模型调用、无 API Key） |

## 能力描述

1. **平台规格表**（2026-Q3 快照）：X 单帖 ≤280 字符/thread ≤7 条；Reddit 标题
   ≤300 字符禁标题党、无上下文裸贴链接 = 最高频删帖原因；PH tagline ≤60 字符 +
   5 图 + ≤60 秒 demo；小红书标题 ≤20 字/正文 ≤1000 字；长文 600-1200 词
2. **信息保真**：改写前列信息点清单（O 必保/△ 可砍）；数字不得改写或换算
   （8s→2.1s 不能写「快 4 倍」）；砍字按「数字 > 场景 > 功能 > 形容词」取舍
3. **调性校准**：Reddit 像同事、X 像朋友、PH 像发布会、小红书像闺蜜——
   换说法不换事实
4. **四步工作法**：拆（信息点）→ 配（结构）→ 写（成稿带实测字数）→
   查（规格核对表，超标回炉）

## 输入规格

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `content` | string | ✅ | 母稿（同源内容） |
| `platforms` | array | ✅ | 目标平台列表（X/Twitter、Reddit、Product Hunt、小红书、Indie Hackers 等） |
| `subreddit` | string | ⬜ | Reddit 目标 sub（决定自推合规检查） |

## 输出规格

- `info_points`：信息点清单（O 必保 / △ 可砍）
- `adapted`：逐平台成稿（带实测字数/条数）
- `checklist`：逐平台规格核对表（字数 / 结构 / 调性 / 合规 / 结论）

## 使用步骤

1. 把 `prompt.txt` 全部内容粘贴为系统提示词（Coze / WorkBuddy / Dify / Claude / ChatGPT 均可）
2. 提供母稿 + 目标平台列表（+ Reddit sub 名）
3. 得到信息点清单、逐平台成稿与规格核对表；人工确认后按排期发布

## 边界（不做的事）

- ❌ 不新增母稿没有的数字、功能与承诺；不换算数字
- ❌ 不在禁止自推的平台/sub 版本放产品链接
- ❌ 超标版本不出手：宁可少一个平台，不发违规版本
- ❌ 平台上限以官方最新公示为准，本表为快照；对外发布保留人工确认

## 调用示例

**输入**（`examples/input.json`，节选）：

```json
{
  "content": "ChurnLens v0.9 上线：Stripe 同步开箱即用（实测接入 15 分钟）、周 cohort 视图、plain-English 流失报告。有用户第 2 周用它找回 3 个要流失的用户。定价 ¥39/月，前 100 名 ¥29。",
  "platforms": ["X/Twitter", "Reddit", "Product Hunt"]
}
```

**输出**（见 `examples/output.md`）：信息点清单 6 条（5 O + 1 △）；
X thread 4 条（首帖 247/280 字符）；Reddit 版标题 62/300 字符、正文 96 词
先讲用法再披露身份；PH tagline 41/60 字符。规格核对 3 平台全过，
1 处「¥39→¥29」促销表述在 Reddit 版按 sub 版规移除。
