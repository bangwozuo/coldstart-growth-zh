# 使用示例

以下示例基于 `examples/input.json` 的真实输入，按 `prompt.txt` 四步工作法产出
（信息点清单、三平台成稿与核对表全文见 `examples/output.md`）。

## 示例 1：标准输入 —— 一篇母稿 → 3 个平台合格版本

**输入**：ChurnLens v0.9 上线母稿 + platforms=[X/Twitter, Reddit, Product Hunt]。

**输出**：X thread 4 条（首帖 247/280 字符）；Reddit r/SideProject 版
（标题 62/300 字符，正文 96 词，末句披露开发者身份）；PH tagline 41/60 字符
+ 配套素材清单。规格核对 3 平台全过。

## 示例 2：整改前后对照 —— 从「一稿直发」到「同源多形」

| 阶段 | 做法 | 结果 |
|---|---|---|
| 改造前 | 同一段产品介绍原样贴 X、Reddit、PH；小红书版连 emoji 都没加 | Reddit 版因无上下文裸贴链接被删；X 触达低于账号均值；PH 首日没回评论 |
| 改造后 | 拆信息点 → 三平台分别构文（X 首帖钩子 / Reddit 先信息后披露 / PH tagline+素材清单） | 无删帖；三个平台字数/结构/调性全部过核对表 |

**关键差异**：一稿多发省的是「想说什么」的时间，适配花的是「怎么说」的时间——
砍掉后者，省下的时间会在删帖与冷触达里加倍还回去。

## 示例 3：数字不改写不换算

母稿「8s→2.1s」在 X 版差点被写成「4x faster」——2.1s 实为 3.8 倍，
「4 倍」是夸大。规格核对表拦截：**换算也是改数字，一律原样报**。

## 示例 4：sub 差异决定版本生死

同一母稿，subreddit 从 r/SideProject 改为 r/SaaS：讨论型 sub 禁自推帖 →
Reddit 帖版本整体不出手，改为「先参与讨论、被问到再披露身份」的评论版本。
适配不是只改字数——**平台/社区规则决定这个版本该不该存在**。

## 示例 5：超标回炉，不硬截断

小红书版首稿正文 1,240 字超上限。处理不是删尾（会砍掉定价信息点），
而是按「形容词 > 功能 > 场景 > 数字」倒序回炉：删空话、合并功能句，
压到 980 字，6 个信息点保留 5 个（△ 级技术栈砍除）。
